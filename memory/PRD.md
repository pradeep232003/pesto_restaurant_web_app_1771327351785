# Jolly's Kafe — Product Requirements (live)

## 1. Vision
Full-stack restaurant ops platform: Apple-inspired UX, multi-location, role-gated admin CRUD, mobile-first JKHive PWA hub for daily/weekly/monthly food-safety routines, dynamic compliance reporting, BI for labour/food/wastage, recipe→inventory auto-deduction.

## 2. Personas
- **Super Admin** — financial BI + AI insights, probe registry edits, calibration history admin
- **Admin (site)** — daily/weekly/monthly routines, staff, inventory, Inspection Mode
- **Staff** — execute routines on mobile

- **Geofenced Clock In/Out MVP** (Feb 2026) — new `/jkhive/clock` page; Clock In/Out tile promoted to top "Operate" row of Workforce (above Shift Mgmt). - **Bank Statement Splitter** (Jul 2026, admin only) — new "Bank Statement" tile on `/jkhive/manager` opens `/jkhive/bank-statements`. Manager uploads a PDF, CSV, or XLSX bank statement (up to 15 MB). Text is extracted locally (`pypdf` for PDFs, `csv` module for CSVs, `openpyxl` for XLSXs) and sent to Claude Sonnet 4.5 via the same zero-SDK httpx pattern used by BI/invoices. The AI classifies every transaction as **income** or **expense**, tags a category slug, and for expenses tries to auto-match against distinct suppliers already in the invoices collection for that location (top 200). A record is persisted per location in the new `bank_statements` collection (period, currency, account_ref, transactions[], totals). Immediately after upload the frontend fetches `/xlsx` and triggers a browser download — a 3-tab workbook (Income, Expenses, Summary) with formatted currency, freeze-panes, coloured headers and running totals. History list shows previous uploads per site with total income/expense/net chips, Download and Delete actions. Endpoints: `GET/POST/DELETE /api/admin/bank-statements`, `GET /api/admin/bank-statements/{id}`, `GET /api/admin/bank-statements/{id}/xlsx`, `GET /api/admin/bank-statements/{id}/file`. Verified end-to-end: extraction, persistence, XLSX generation with correct tabs/totals/formatting all working; AI classification uses the same `httpx → api.anthropic.com` path proven in prod.
- **Bank Statement chunked AI processing** (Jul 2026) — fixed "Load failed" on large PDFs (e.g. 22-page 3-month statements). Root cause: single Claude call was hitting the 8 000-token output cap AND large statements risked exceeding Cloudflare's ~100 s ingress timeout. Now `_classify()` splits the extracted text into ~15 KB chunks along natural `--- Page N ---` boundaries (CSV/XLSX fall back to line-based chunking), then runs up to 4 chunks in parallel via `asyncio.gather` + `Semaphore`. Per-chunk `httpx` timeout is 120 s. Results are merged (first non-empty period/currency/account wins, transactions concatenated + deduped by (date, description, amount, type)). Total wall-clock for a 22-page statement now ~30–40 s, comfortably under the ingress cap. Verified chunking logic locally against synthetic 22-page and CSV inputs.
- **Bank Statement — Python parser + Rules manager** (Feb 2026) — moved off Anthropic AI as the default engine to save tokens. New `bank_statement_parser.py` uses `pdfplumber` for column-aware PDF layout extraction (uses the actual `Details`, `Paid in`, `Paid out` column positions), regex date/amount rules, and `bank_rules` collection for user-defined category mappings. Suppliers auto-match against distinct invoices for that location by exact `(amount, date ± 3 days)`. New `/jkhive/bank-rules` page for CRUD on rules (keyword or regex → category). "Add rule from this row" button surfaces on unmatched rows directly in the Details tab. Re-classify endpoint runs Python parser + invoice reconciliation.
- **Bank Statement UI cleanup** (Feb 2026) — removed the "Local Python parser" helper copy, removed auto-XLSX-download on upload success (managers hit the row Download button when ready), removed the AI/sparkle fallback button from the row actions (Python is the only engine now), widened the Date column on the Details tab so `dd MMM yyyy` no longer wraps. Backend `POST /{sid}/reclassify` already calls `_enrich_with_invoices` so newly-added invoices get matched on re-classify.
- **Bank Statement XLSX download bug fix** (Feb 2026) — root-cause of "Download XLSX gives error" in prod was `openpyxl.utils.exceptions.IllegalCharacterError`: `pdfplumber` PDF text extraction routinely injects ASCII control characters (`\x00`, `\x0c` form-feed between pages, `\x1f`, etc.) into transaction descriptions, and openpyxl refuses to write them to a cell. Fix: `_build_split_xlsx()` now runs every string cell through an `_s()` sanitiser that strips the illegal-XML control-character range (`\x00-\x08\x0b\x0c\x0e-\x1f`) and coerces `datetime` values to ISO strings. Wrapped both XLSX endpoints (`/{sid}/xlsx` and `/aggregate/xlsx`) in try/except so any future openpyxl failure is logged with stack trace and returned as HTTP 500 with a real detail string. Frontend `api.bankStatementXlsxUrl` + `bankStatementsAggregateXlsxUrl` now read the body as text first and surface the real backend message (JSON `detail`, Cloudflare HTML, or empty body diagnostic) instead of a silent "XLSX download failed (500)". Verified with synthetic transactions containing `\x00`, `\x0c`, `\x1f`.
- **Bank Statement delete — typed confirmation** (Feb 2026) — replaced the one-tap `window.confirm` with `window.prompt` that shows the number of transactions that will be lost and requires the user to type `DELETE` in capitals before the API call fires. Guards against accidental swipes/clicks on the delete pill.
- **Bank Statement invoice match — stale ref fix** (Feb 2026) — bug: bank rows could show a "Matched Invoice" reference that no longer existed in the invoices collection (the invoice was deleted after the statement was uploaded). Two root causes: (1) `_enrich_with_invoices` only set new matches, never cleared stale ones; (2) the Details "Matched Invoice" column silently fell back to `matched_supplier` (a fuzzy supplier-name hit that is NOT an invoice) making a supplier hint look identical to a real invoice link. Fix: enrichment now loads the current valid invoice-id set and DROPS any `matched_invoice_id`/`matched_invoice_ref` on a txn whose linked invoice no longer exists — happens automatically on every upload AND on Re-classify. The Details table and XLSX Expenses tab now only render `matched_invoice_ref` when `matched_invoice_id` is present; a supplier-only fuzzy match is shown in muted italic text with a small `no invoice` chip so it's unambiguous.

## 8. Key invariants
- All compliance "applicability" must use the configuration source (e.g. probes registry), not historical records, to decide N/A vs Missing.
- `applicable_routines` array stores both daily AND weekly routine keys; expand "empty = all" using `ALL_ROUTINE_KEYS`.
- For checklist-runs-backed compliance, a period only counts as complete when the UNION of ticked indices across runs covers all visible items.
- `?back=` parameter for every JKHive sub-route to preserve native mobile back behaviour.
- Admin-only routes: `/api/admin/bi`, `/api/admin/bi/ai-insights`, `/api/admin/inspection/pack`, probe PATCH/DELETE, calibration PATCH/DELETE.
- Probe names unique per location (case-insensitive); enforced both server-side and pre-validated client-side.
- LLM responses cached for 30 min keyed on (period + filter + data digest); refresh button forces a re-run.
- All audit-pack views must have a `@media print` CSS block.
